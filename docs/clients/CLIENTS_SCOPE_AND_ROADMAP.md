# نطاق وحدة الموكلين وخطة التنفيذ المرحلية

| الحقل | القيمة |
|---|---|
| المرحلة | **توصيف نطاق وخطة** — وليست إذنًا بالتنفيذ |
| الحالة | **مقترح — بانتظار اعتماد صاحب المشروع** |
| التاريخ | 2026-10-18 |
| الوثيقة الأم | كل وثائق الحزمة |

## 1. كيف قُسّم النطاق

المعيار المعتمد في التصنيف ليس **سهولة التنفيذ** بل:

> **أهمية الوظيفة للمكتب + اعتمادياتها المعتمدة.**

لذلك قد تكون وظيفة **تحتاجها المكتبة جدًا** لكنها في الفئة «ج» لأنها تعتمد على نظام عام لم يُنفذ بعد (مثل استيراد منظبط، أو مخطط تخصيص عام). والعكس: وظيفة قد تكون سهلة التنفيذ لكنها **لا تخدم مهمة** فلا تدخل النطاق أصلًا.

| الفئة | المعنى |
|---|---|
| **أ** | ضرورية للإصدار الأول من وحدة الموكلين |
| **ب** | مهمة ويمكن تنفيذها في مرحلة لاحقة |
| **ج** | متقدمة، أو تعتمد على أنظمة عامة لم تُنفذ بعد |

## 6. خطة التنفيذ المرحلية (مقترحة)

> **هذه خطة تخطيط لا جدول زمني ولا تصريح تنفيذ.** كل مرحلة تحتاج اعتمادًا صريحًا قبل بدئها.

### المرحلة 0 — اعتماد المواصفات الوظيفية

| البند | الوصف |
|---|---|
| **النطاق** | اعتماد الرؤية والرحلات ونطاق الوحدة |
| **المخرجات** | مواصفة رحلات معتمدة؛ قائمة قرارات مغلقة |
| **الاعتماديات** | لا شيء |
| **معيار القبول** | اعتماد صريح لـ `CLIENTS_MODULE_VISION.md` و`CLIENTS_USER_JOURNEYS.md`؛ حسم `CD-01` و`CD-02` و`CD-03` و`CD-05` |
| **قرارات مطلوبة قبل البدء** | `CD-01`…`CD-05` |

### المرحلة 1 — اعتماد نموذج البيانات والعلاقات

| البند | الوصف |
|---|---|
| **النطاق** | الطبقات الثلاث، ملكية كل حقل، الثوابت |
| **المخرجات** | نموذج منطقي معتمد + مصفوفة النطاقات |
| **الاعتماديات** | المرحلة 0 |
| **معيار القبول** | اعتماد `CLIENTS_DATA_MODEL.md`؛ لا حقل بلا نطاق معلن؛ لا تعارض مع ADQ-01…ADQ-45 |
| **قرارات مطلوبة** | `CD-01`, `CD-04`, `CD-07`, `CD-08` |

## 7. تسلسل الاعتماديات الحرج

```
CD-01 (ما هو الموكل)
   ├──▶ نموذج البيانات ──▶ المرحلة 4 ──▶ 5 ──▶ 6/7 ──▶ 8 ──▶ 10 ──▶ 11
CD-02 (من يملك كتابة الهوية)
   └──▶ عقد C1 ──────────▶ المرحلة 3 ──▶ المرحلة 8
CD-05 (معيار منع التكرار)
   └──▶ سلوك الإضافة ────▶ المرحلة 5
القرارات التقنية (لغة/إطار/محرك)
   └──▶ المرحلة 4 (حاجز مطلق)
```

> **ملاحظة**: المرحلة 4 **موقوفة** على قرار تقني لم يُتخذ بعد (`docs/TECHNICAL_DECISIONS_PENDING.md`). هذه الحزمة لا تُقدّم توصية تقنية، لأنها خارج صلاحية هذا الأمر — لكنها تُظهر مكان الاعتماد.

## 8. معايير قبول عامة تسري على كل المراحل

| # | المعيار |
|---|---|
| Q1 | لا تعارض مع ADQ-01…ADQ-45 |
| Q2 | لا كيان أو حقل بلا نطاق معلن (تثبيت/قاعدة) |
| Q3 | كل عملية ذرّية وقابلة لإعادة المحاولة بلا تكرار أثر |
| Q4 | لا تعارض صامت؛ التعديلات المتعارضة محفوظة للمراجعة |
| Q5 | الصلاحيات مطبَّقة على البيانات لا على الواجهة |
| Q6 | لا ذاكرة محلية لبيانات لا يملكها المستخدم صلاحيتها |
| Q7 | لا حقل إلزامي بلا مبرر مكتوب |
| Q8 | كل شاشة لها مهمة إسناد |
| Q9 | لا أرقام أداء غير مقيسة |
| Q10 | لا تعديل خارج نطاق الوحدة دون موافقة |

## 9. خلاصة

1. **25 وظيفة** في الفئة (أ)، و**10** في (ب)، و**12** في (ج) — التوزيع مبني على الأهمية والاعتماديات لا على السهولة.
2. **المزامنة والعمل دون اتصال في الفئة (أ)** لأن ADQ-05 وADQ-18 يوجبان ذلك في الإصدار الأول.
3. **البحث الشامل في الفئة (أ)** لأن ADQ-41 يوجبه.
4. **الدمج في الفئة (ب)** لأن ADQ-13 يشترط صراحةً ومراجعة وصلاحية، مع بقاء قاعدة «عدم التكرار التلقائي» سارية في المرحلتين.
5. **الحذف النهائي في الفئة (ج)** لأن ADQ-31 يجعله استثنائيًا ومقيّدًا.
6. **المرحلة 4 موقوفة على قرار تقني** لم يُتخذ، وهذه الحزمة لا تخرجه.
