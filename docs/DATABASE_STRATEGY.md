# متطلبات تعدد قواعد البيانات

- [REQ-008] قواعد مستقلة متعددة، بلا مدة ثابتة، تضم بياناتها القانونية والمالية والمستندات، ويُنشأ الجديد وفق الحجم والأداء والتنظيم.
- [REQ-009] التبديل السهل، وإمكان فتح أكثر من قاعدة إذا سمحت البنية، ومنع اختلاط السجلات والبيانات المالية.
- [REQ-010] بحث سريع داخل القاعدة النشطة، وبحث شامل مستقل ضمن القواعد المتاحة للمستخدم.
- [REQ-011] مفهوم هوية مشتركة للأشخاص عبر القواعد دون تكرار غير منضبط. المطلوب علاقة مفاهيمية لا اختيار موضع تخزين.
- [معتمد] القرار المعماري الثاني (انظر `DECISIONS.md`): لكل شخص هوية موحدة وثابتة على مستوى المشروع، وتحتفظ كل جهاز بنسخة محلية من سجل الأشخاص المشترك للاستخدام دون اتصال، وتُنقل تغييراته بين الأجهزة عند توافر وسيلة اتصال تسمح بالمزامنة، وتُحفظ تعديلاته المتعارضة دون استبدال صامت. اشتراك الأشخاص في الهوية لا يجعل الملفات القانونية أو القضايا أو البيانات المالية تنتقل بين القواعد؛ تظل مستقلة لكل قاعدة.
- [REQ-012] تصور نقل ملف كامل مستقبلًا يشمل البيانات الأساسية والقضايا والمسارات والجلسات والإجراءات والمستندات والأشخاص والماليات وتتبع المصدر والانتقال.
- [REQ-019] استقلال النسخ الاحتياطي والاستعادة لكل قاعدة، مع مراعاة الاعتماديات المشتركة.

[يحتاج قرار] مكان التخزين المرجعي للسجل المشترك، مركزية/توزعه وتفاصيل بنيته، والتقنية المستخدمة لتخزينه أو مزامنته، وآلية إنشاء الهوية الموحدة وتمثيلها تقنيًا، واكتشاف المكررين ودمج سجلاتهم، ومعالجة التعديلات المتعارضة واعتماد التعديل النهائي، وسلوك السجل عند نقل قاعدة، وعرض بياناته التاريخية والحالية، ومنع الازدواجية والتعرف على الشخص. هذه تفاصيل خارج نطاق القرار المعماري وبانتظار قرار مستقل. كما لم يحسم فتح قواعد متعددة أو شكل إدارتها.

[يحتاج قرار] هل نقل الملف نقل أم نسخ، مصير المصدر، المعرفات، العلاقات المشتركة، القيود المحاسبية، التحقق والتنفيذ. تبقى قواعد البيانات مستقلة؛ لا يُستنتج من البحث الشامل أنها تندمج أو تتشارك سجلاتها.
