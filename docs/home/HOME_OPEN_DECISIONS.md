## 1. كيف تُقرأ هذه الوثيقة

كل قرار يعرض: السؤال بدقة، ولماذا هو مطلوب الآن، والبدائل على مستوى السلوك لا التقنية، والافتراضي المقترح (ليس قرارًا)، وما يتغير بحسب الاختيار، وأثر التأجيل.

> **قاعدة**: لا يُختار هنا خطًا ولا إطارًا ولا محركًا؛ التقنيات مؤجلة في `docs/TECHNICAL_DECISIONS_PENDING.md` ولا تملك هذه الوثيقة صلاحية الحسم فيها. وتظل البوابتان في `HOME_DESIGN_REVIEW.md` نافذتين: اعتماد التصميم ثم اعتماد التقنية عند التنفيذ.

## 3. تفاصيل القرارات

### HD-01 — قاعدة ترتيب الأولويات و«سبب الظهور»

| البند | الوصف |
|---|---|
| **السؤال** | ما القاعدة المعتمدة لترتيب صفوف المجرى وشروحات «سبب الظهور»؟ |
| **لماذا الآن** | هي خوارزمية الصفحة القلبية؛ قاعدة غامضة تخالف الأمر §7 |
| **البديل (أ)** | **استحقاق صريح فقط:** متأخر (الأقدم أولًا) ← اليوم ← قريب ← انتظار؛ السبب مشتق من التاريخ والحالة المسجَّلين |
| **البديل (ب)** | (أ) + وزن نوع العمل (جلسة > مهمة) — **يخالف عدم افتراض أهمية الجلسة** |
| **البديل (ج)** | ترتيب يفضله المستخدم فقط |
| **الافتراضي المقترح** | **(أ)** — شفاف وقابل للتفسير ومتوافق مع «لا خوارزمية غامضة» |
| **ما يتغير** | (ب) يفرض تفضيلًا قانونيًا غير مبرر؛ (ج) وحده يخل بالوعد «الترتيب الجاهز دون إعداد» |
| **أثر التأجيل** | لا يمكن اعتماد بنية المجرى ولا H1 |

### HD-02 — نطاق شريط «الآن»

| البند | الوصف |
|---|---|
| **السؤال** | ما معايير دخول العمل إلى شريط «الآن» وعتبات التقادم؟ |
| **لماذا الآن** | يحدد حجم الانتباه الفوري ومن يظهر فيه |
| **البديل (أ)** | جلسات اليوم + أعمال متأخرة تجاوزت حدًا (افتراضي يومان) + انتظار قرار تجاوز (افتراضي 3 أيام) |
| **البديل (ب)** | جلسات اليوم فقط |
| **البديل (ج)** | يدوي بالكامل (المستخدم يثبّت) |
| **الافتراضي المقترح** | **(أ)** بعتبات قابلة للضبط عبر التخصيص |
| **ما يتغير** | (ب) يهمل المتأخر الحاد؛ (ج) يخالف «الترتيب الجاهز» |
| **أثر التأجيل** | يجمّد تصميم الشريط الأول |

### HD-03 — تمثيل الجلسات في المجرى أم السكة

| البند | الوصف |
|---|---|
| **السؤال** | هل الجلسة المستحقة صف كامل في المجرى، أم تقتصر على سكة الجاهزية مع بقائها في «الآن»؟ |
| **لماذا الآن** | يحدد ازدحام المجرى وتكرار الجلسة المحتمل |
| **البديل (أ)** | صف في المجرى (مستحقة) + سكة للجاهزية فقط (تكميلية، P3) |
| **البديل (ب)** | السكة فقط + شريط «الآن» |
| **الافتراضي المقترح** | **(أ)** — مع قائمة أعمال الجلسة داخل صفها لا كصفوف مستقلة |
| **ما يتغير** | (ب) يضعف الوصول المباشر للجلسة من مجرى اليوم |
| **أثر التأجيل** | يمنع تثبيت تشريح الصف |

### HD-04 — ملكية وآلية حفظ «استئناف»

| البند | الوصف |
|---|---|
| **السؤال** | أين يُحفظ «آخر فتح»: ذاكرة جلسة فقط، أم تفضيلات المستخدم المزامنة، أم سجل نشاط عام؟ |
| **لماذا الآن** | خصوصية + مزامنة + تكلفة |
| **البديل (أ)** | تفضيلات المستخدم (تُزامن) بمعرّفات فقط |
| **البديل (ب)** | ذاكرة جلسة/جهاز فقط (لا مزامنة) |
| **البديل (ج)** | مشتق من سجل النشاط (ADQ-32) |
| **الافتراضي المقترح** | **(أ)** مع حد صارم: معرّفات + وقت فقط |
| **ما يتغير** | (ب) لا يعمل عبر الأجهزة؛ (ج) يحمّل سجل التدقيق وظيفة عرض |
| **أثر التأجيل** | وحدة «استئناف» تعمل محليًا بالبديل (ب) مؤقتًا |

### HD-05 — مصادر «حصيلة اليوم» وتعريف «أُنجز»

| البند | الوصف |
|---|---|
| **السؤال** | من أين تأتي بيانات الحصيلة، وماذا يعني «أُنجز اليوم» تحديدًا؟ |
| **لماذا الآن** | H4 بلا تعريف دقيق يتحول لتقارير موازية أو أرقام كاذبة |
| **البديل (أ)** | استعلامات جاهزة من كل وحدة مالكة؛ «أُنجز» = اكتمل/سُجلت نتيجته اليوم بتوقيت مرجعي |
| **البديل (ب)** | محرك تقارير عام مستقل تقرأه الصفحة |
| **الافتراضي المقترح** | **(أ)** |
| **ما يتغير** | (ب) يعتمد على منظومة تقارير غير موجودة وقد يخلق موازاة |
| **أثر التأجيل** | تعطيل A-08 |

### HD-06 — أوضاع العرض الجاهزة

| البند | الوصف |
|---|---|
| **السؤال** | هل تعتمد الأوضاع الأربعة المقترحة (افتراضي/جلسات أولًا/متابعة إدارية/هدوء)؟ |
| **الافتراضي المقترح** | اعتماد «الافتراضي» و«جلسات أولًا» أولًا، والبقية لاحقًا |
| **أثر التأجيل** | التفضيلات الفردية تكفي للبداية |

### HD-07 — العائلة الخطية العربية

### HD-10 — حدود البيانات المالية والحساسة

| البند | الوصف |

| **الافتراضي المقترح** | **لا مالي في الإصدار الأول**؛ الأسماء وفق الصلاحيات فقط |
| **أثر التأجيل** | يبقي الصفحة خفيفة؛ أي إضافة لاحقة تحتاج قرارًا صريحًا |

### HD-11 — التصفية بالمسؤول/المسندة إليّ

| **الافتراضي المقترح** | خيار + تفضيل افتراضي قابل للضبط؛ الظهور يتبع دعم المصدر |
| **أثر التأجيل** | المجرى يعمل بالكل |

### HD-12 — قواعد التنبيهات الاستعدادية للجلسات

### HD-14 — الوضع الداكن واعتماد RTL

| البند | الوصف |
|---|---|
| **السؤال** | (أ) هل يدخل الوضع الداكن الإصدار الأول؟ (ب) هل يُعتمد RTL والتجربة العربية كمتطلب منتج رسمي للبرنامج؟ |
| **ملاحظة السند** | `PROJECT_VISION.md` تسجّل أن توجهات الواجهة «ليست متطلبات معتمدة لهذه المرحلة»؛ وأمر هذه المرحلة يطلب تجربة RTL كاملة (تعارض E-01) |

### HD-15 — الإجراءات الموجهة لوحدات غير منفذة

| البند | الوصف |
|---|---|
| **السؤال** | عند تنفيذ الصفحة قبل اكتمال وحداتها: هل تُحجب الإجراءات الغائبة (كما يوصي التصميم)، أم تُعرض معطَّلة مع وسم «قريبًا»، أم تُنفذ بروابط محاكاة داخل بيئة التطوير فقط؟ |
| **لماذا الآن** | قرار بنيوي في مسار التنفيذ وسلامة الوعد بالواجهة |
| **البديل (أ)** | **الحجب التام** في الإصدارات العامة + محاكي عقد معتمد للتطوير والاختبار |
| **البديل (ب)** | إظهار معطَّل مع وسم |
| **البديل (ج)** | تنفيذ إجراءات محدودة داخل الصفحة مؤقتًا (مخالف لـP5) |
| **الافتراضي المقترح** | **(أ)** — يحفظ «الواجهة لا تكذب» ويمنع النظام الموازٍ |
| **ما يتغير** | (ب) يوحي بوجود وظائف؛ (ج) يخلق المنظومة الموازية الممنوعة صراحة |
| **أثر التأجيل** | لا يمكن بدء المرحلة 3 من `HOME_SCOPE_AND_ROADMAP.md` |

## 4. العلاقة بقرارات حزمة الموكلين

لا تتقاطع `HD` مع `CD` رقميًا؛ وما يتقاطع موضوعيًا يُحسم كل في موضعه: مثلًا `CD-01` (طبيعة الموكل) يحكم وحدة الموكلين، و«مكتب اليوم» يكتفي بعرض الاسم كما تحدده الوحدة. ولا يُعاد طرح أي قرار معتمد من ADQ.
