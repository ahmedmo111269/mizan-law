# تصميم الهاتف والكمبيوتر وRTL

> **مواصفات بنيوية مقترحة، وليست CSS أو نموذجًا إنتاجيًا.** العرض أدناه عرض مساحة العمل المنطقية، لا عدد بكسلات حساس الشاشة. نفس عقود البيانات وقواعد الأهلية والصلاحية على كل الأجهزة؛ يتغير العرض فقط.

## 1. قواعد التحول

1. يبدأ التصميم بعمود واحد من 320px، ويكبر النص مع إعداد الجهاز بدل تصغيره لملاءمة أعمدة كثيرة.
2. أقل من 600: أدوات البحث/جديد/الأقسام في شريط سفلي مسمى؛ الرأس للسياق والقاعدة.
3. من 600 إلى أقل من 1024: البحث والأفعال في رأس مرن على صفين عند الحاجة، وقائمة واحدة؛ تفاصيل في مساحة مستقلة لا عمود ضيق.
4. من 1024: يمكن فتح سياق على اليسار، والقائمة الأساسية على اليمين. إذا لم يكف العرض الفعلي بعد التكبير، يعود الوضع الأحادي بدل ضغط النص.
5. أقصى عرض محتوى مقترح 1280؛ لا تتمدد الأسطر على شاشة عريضة بلا حد. الأقسام لا تصبح جزرًا إحصائية.
6. لا حجز لعمود تفاصيل فارغ. بلا اختيار، تستخدم القائمة العرض المتاح؛ بطاقات الاستئناف لا تملأ الفراغ اصطناعيًا.

هذه نقاط سلوكية مقترحة HD-01/15، لا اعتماد إطار متجاوب أو اختيار نوع التطبيق.

## 2. مصفوفة العروض الستة

| العرض | الهوامش / العرض المتاح | الرأس والأدوات | قائمة العمل | السياق والبحث والتخصيص |
|---|---|---|---|---|
| **320px** | 12 لكل جانب؛ 296 محتوى | اسم القاعدة في سطر يمكن التفافه، العنوان والنطاق تحته؛ شريط سفلي 3 أهداف | عمود واحد، نص 16، مرشحات تلتف؛ معاينة 3 لكل مجموعة؛ أفعال في سطر مستقل عند الحاجة | بحث وتفاصيل وتخصيص مساحة كاملة؛ لا درج جانبي يترك هامشًا ضيقًا |
| **360px** | 16 لكل جانب؛ 328 محتوى | نفس الهاتف؛ قد يجتمع التاريخ والنطاق إن اتسعا دون قص | صف 3–4 أسطر مرنة؛ موعد وسبب لا يختفيان | أوراق خيارات قصيرة فقط؛ ما يحتاج كتابة أو تفاصيل طويلة كامل المساحة |
| **390px** | 16 لكل جانب؛ 358 محتوى | نفس دلالة الأدوات، لا إضافة أيقونات لمجرد وجود مساحة | قد يجتمع الموعد والجهة في سطر؛ لا تحويل إلى عمودين | ورقة مرشحات بارتفاع قابل للتمرير؛ البحث والتفاصيل كاملان |
| **768px** | 24 لكل جانب؛ 720 محتوى | شريط علوي على صفين: سياق/أفعال ثم بحث واسع؛ لا شريط سفلي مكرر | قائمة واحدة، معلومات ثانوية أكثر على السطر، 5 معاينات لكل مجموعة إن سمح تكبير النص | مساحة تفاصيل مستقلة مع رجوع؛ ليست بطاقة ثانية لكل عنصر |
| **1024px** | 24 لكل جانب؛ 976 محتوى | بحث داخل الرأس المرن؛ يحتفظ بصف ثانٍ إن لم تتسع العناصر | عند فتح السياق: قائمة 632 + فجوة 24 + سياق 320؛ بلا سياق قائمة كاملة | السياق على اليسار، بحث عام واسع غير مرتبط بالعمود؛ تخصيص في حوار أو مساحة مستقلة |
| **1440px** | حد محتوى 1280 وهوامش 80 | رأس بمحاذاة المحتوى؛ بحث مرن حتى نحو 480 دون دفع القاعدة خارج العرض | عند فتح السياق: قائمة 896 + فجوة 24 + سياق 360؛ بلا اختيار عرض كامل | سياق واحد، لا عمود إحصاءات ثالث؛ لا توسيع تلقائي للمستندات أو كل العلاقات |

حد معاينة 5 عند 768 وما فوق مقترح عرض وليس تغييرًا لترتيب العمل. إذا أدى التكبير إلى النمط الهاتفي تستخدم حدوده. ارتفاعات الرأس والصفوف الدنيا ليست قيود قص؛ قد يزيد ارتفاعها مع النص والتكبير.

## 3. مخطط الهاتف: 320–390px

المخطط يُقرأ **من أعلى إلى أسفل**. ترتيب العناصر داخل كل سطر يُنفّذ منطقيًا من اليمين إلى اليسار؛ رسم النص داخل Markdown ليس مرجع محاذاة بكسليًا.

```text
┌──────────────────────────────┐
│ H-01 ميزان · القاعدة النشطة   │
│      {اسم كامل قابل للالتفاف} │
│ H-09 {الحالة الحقيقية}        │
├──────────────────────────────┤
│ H-04 مكتب اليوم              │
│      {التاريخ} · {النطاق}     │
│ [العمل] [الأجندة]            │
│ [تصفية] [القادم]             │
│ {مداخل مجموعات العمل}        │
├──────────────────────────────┤
│ H-05 {سبب المجموعة} [الكل]   │
│ نوع · عنوان السجل            │
│ دلالة الموعد · السياق        │
│ سبب الظهور                   │
│ [إجراء متاح] [تفاصيل]        │
│ … ثم المجموعات الأخرى        │
├──────────────────────────────┤
│ H-07 استئناف إن توفر         │
│ H-08 مراجعة اليوم إن توفرت    │
├──────────────────────────────┤
│ [بحث]   [جديد]   [الأقسام]    │
│       مساحة أمان الجهاز       │
└──────────────────────────────┘
```

هذا مخطط **تكوين** لا عينة منتج؛ الأقواس تشير إلى حقول مصدر، لا أسماء أو أعمال وهمية. إذا كانت خدمة البحث/الإضافة غير منفذة لا يظهر زر يعمل شكليًا. يظل مدخل الأقسام المتاحة، وتتغير مساحة الأدوات بحسب القدرات.

### أول شاشة في الهاتف

الأولوية: القاعدة ← الاستثناء المؤثر إن وجد ← عنوان اليوم/النطاق ← مداخل المجموعات ← بداية الأعمال. لا يُوعد بظهور أول سجل في عدد بكسلات ثابت عند تكبير النص أو طول تحذير؛ الأهم أن مدخل الأعمال قابل للوصول وأن الأشرطة لا تحجبه. يمكن التمرير الرأسي الطبيعي، لا شريطين ثابتين كبيرين يحاصران المحتوى.

## 4. مخطط الكمبيوتر: 1024–1440px

في الشكل التالي: **يمين الرسم يمثّل بداية القراءة العربية**، والقائمة الرئيسية تبقى قبل السياق في ترتيب الوصول المنطقي.

```text
┌───────────────────────────────────────────────────────────────────┐
│ أدوات/جديد/أقسام      بحث عام بنطاق ظاهر       القاعدة · ميزان     │
├───────────────────────────────────────────────────────────────────┤
│          حالة التشغيل الفعلية عند الحاجة                         │
│          مكتب اليوم · التاريخ · النطاق · العدسة/المرشحات           │
│          مداخل المجموعات + كل الأعمال + تخصيص                    │
├────────────────────┬──────────────────────────────────────────────┤
│ H-06 سياق مختار    │ H-05 دفتر العمل الرئيسي                      │
│ نوع/عنوان/موعد     │ سبب المجموعة                        عرض الكل │
│ علاقات متاحة       │ نوع · عنوان · موعد · سياق · فعل               │
│ آخر نتيجة مسجلة    │ الصف التالي دون تكرار بطاقة إحصاء             │
│ استعداد حقيقي      │ المجموعة التالية ومدخل قائمتها الكاملة        │
│ فتح المصدر/إجراء   │                                              │
├────────────────────┴──────────────────────────────────────────────┤
│ استئناف محدود / مراجعة اليوم عند توفر المصدر                     │
└───────────────────────────────────────────────────────────────────┘
```

لا اختيار: لا يظهر العمود الأيسر. تحديد عنصر جديد يتم بزر «تفاصيل»، والعنوان يظل فتحًا مباشرًا للمصدر. لا نافذتان لتحرير سجلين في الرئيسية، ولا تمرير مستقل طويل لكل مجموعة؛ يفضل تمرير صفحة واحد، مع تمرير تفاصيل محدود فقط إذا دعت الحاجة واختُبرت الوصولية.

## 5. التحولات الدقيقة للمكونات

| المكون | الهاتف | الكمبيوتر | ما لا يتغير |
|---|---|---|---|
| اسم القاعدة | نص ملتف أو صف ثانٍ؛ اسمه الكامل متاح دون Hover | داخل الرأس ومبدل واضح | هوية القاعدة جزء دائم من السياق |
| البحث | مساحة كاملة، نطاق أعلى النتائج، لوحة مفاتيح مناسبة | سطح بحث عام بعرض ملائم، تصنيف ونتائج محدودة | نفس HC-07 ونفس المصادر والقيود |
| المرشحات | زر «تصفية» يذكر عدد المرشحات النشطة، خيارات مسماة وتطبيق/إلغاء | شريط مختصر؛ مزيد من المرشحات في سطح واحد | لا تطبيق مرشحات مختلفة ضمنيًا حسب الجهاز |
| الصف | 3–4 أسطر أو أكثر عند التفافها؛ الفعل تحت الوصف | أعمدة مرئية مرنة للوقت/النص/الفعل دون جدول عريض إجباري | النوع والموعد والسبب والعنوان لا تُحذف بالكثافة |
| المعاينة | صفحة/مساحة كاملة تملكها الوحدة مع «العودة للأعمال» | سياق يسار القائمة إذا دعم المالك معاينة | لا نقل منطق التحرير أو الجلب إلى home |
| الجديد | قائمة قصيرة قابلة للمس، ثم نموذج المالك | قائمة مرتبطة بزر الرأس | إنشاء الوحدة نفسها، لا نموذج هاتف مختلف منطقيًا |
| ترتيب الأقسام | أزرار «قبل/بعد» وتسميات، والسحب اختياري فقط | نفس البديل باللوحة، وسحب إن اعتُمد | التخصيص من HC-10 ولا تغيير أولوية السجلات |
| مراجعة اليوم | قائمة قراءة تسلسلية في المالك | عرض أوسع للبنود والعلاقات | لا أرقام ملخصة بدل البيانات على الهاتف |

## 6. اللمس والاستخدام بيد واحدة

- هدف داخلي مقترح **44×44 على الأقل** لكل فعل، والأفعال الرئيسية بارتفاع 48 حيث تسمح المساحة. هذا هدف تصميم أقوى من بعض الحدود الدنيا المعيارية، لا ادعاء امتثال تلقائي.
- شريط الهاتف السفلي نحو 64 + مساحة أمان النظام، بثلاثة أهداف متساوية عند توفرها. لا أيقونات بلا أسماء ولا زر عائم يغطي صف عمل.
- فجوة 8 على الأقل بين الأهداف الصغيرة المتجاورة؛ عند ضيقها تلتف الأفعال إلى سطر جديد ولا تصغر إلى 24.
- لا سحب يمين/يسار لإتمام مهمة أو حذفها، ولا ضغط طويل وحيد لفتح الإجراءات. كل وظيفة لها زر واضح.
- إدراك حدود اليد الواحدة: تبديل القاعدة في الأعلى أقل تكرارًا، بينما البحث وبدء العمل قريبان من الإبهام. لا ننقل تحذيرات السلامة بعيدًا لتسهيل الشكل.

## 7. لوحة المفاتيح والمساحات الآمنة

- عند فتح البحث على الهاتف ينتقل التركيز للحقل ويختفي شريط الأدوات السفلي غير اللازم داخل مساحة البحث، فلا يقع فوق لوحة المفاتيح أو النتائج.
- سطح البحث قابل للتمرير، وزر الرجوع ومسح النص والتبديل بين النطاقات متاحون دون تغطية. تقصير النتائج لا يغير النطاق.
- نموذج المالك مسؤول عن عدم تغطية الحقل النشط وأزرار الحفظ/الخطأ؛ لا تستنسخ الرئيسية سلوك نموذج مختلف. في شاشة قصيرة تفضّل أزرار ضمن التدفق بدل رأس وتذييل يستهلكان الارتفاع كله.
- تُحترم حواف العرض والنتوءات ومؤشر العودة في نظام الهاتف. أسفل القائمة حيز يساوي الأداة الثابتة ومساحة الأمان حتى يظهر آخر زر كاملًا.
- الرجوع في Android أو إغلاق سطح البحث يعيد النص/الموضع ضمن الجلسة. الرجوع من نموذج غير مكتمل يحترم حارس المالك، لا إغلاق آلي أو حفظ جزئي.
- الاتجاه الأفقي للهاتف يعامل بحسب العرض الفعلي والارتفاع؛ لا يفرض عمود سياق إذا لم تكف مساحة القراءة أو كُبر الخط.

## 8. RTL والتكبير والتنقل المساعد

| الحالة | السلوك المطلوب |
|---|---|
| بداية/نهاية السطر | بداية منطقية يمين في العربية، لا قيم موضعية تتبدل عشوائيًا بين الوحدات |
| رقم قضية/هاتف/مرجع مختلط | مقطع ذو اتجاه مناسب يحفظ ترتيب الأرقام والشرطات، مع تسمية عربية؛ لا قلب النص يدويًا |
| عنوان طويل واسم قاعدة طويل | التفاف طبيعي؛ لا قطع النوع/المصدر أو الاعتماد على Tooltip |
| تكبير النص 200% | زيادة الارتفاع والالتفاف، وتحول إلى عمود واحد عند الحاجة، بلا فقد أفعال |
| إعادة تدفق بمكافئ 320px / تكبير 400% على عرض مناسب | لا تمرير أفقي غير مقصود ولا تمرير في اتجاهين لإنجاز مهمة أساسية |
| قارئ شاشة | عنوان الصفحة ثم عناوين المجموعات وقوائمها؛ ترتيب منطقي ثابت عند انتقال السياق بصريًا إلى اليسار |
| تبويب لوحة المفاتيح | التركيز لا يقفز إلى سياق خارج الشاشة ولا يُحجب بالشريط الثابت؛ رابط تخطٍّ إلى الأعمال |
| قوائم وأوراق | إغلاق مسمى، رجوع للعنصر المُطلِق، وحصر التركيز في الحوار فقط؛ لا اعتماد على Hover |

القياسات واجهة/نص لا أحجام صور. لا توجد صور غنية أو مخططات بيانية تتطلب استثناء إعادة تدفق في هذا التصميم.

## 9. اختبارات القبول المستقبلية لكل عرض

| العرض | سيناريو القبول |
|---|---|
| 320 | اسم قاعدة وعنوان طويلان + مصدر جزئي + خط كبير: فتح البحث، مرشح المتأخر، إجراء صف، العودة؛ لا فقد نص أو هدف لمس |
| 360 | فتح لوحة المفاتيح وتغيير نطاق البحث ثم فتح نتيجة والعودة؛ لا شريط يغطي الحقل أو آخر نتيجة |
| 390 | 20 متابعة بصفحات محدودة؛ عمل واحد لكل هوية؛ الأفعال لا تُفتح بالسحب فقط |
| 768 | تنقل باللمس وباللوحة، تفاصيل كاملة ثم رجوع؛ لا عمودان متزاحمان ولا صفان لنفس السجل |
| 1024 | فتح سياق بجانب القائمة، ثم تكبير النص حتى التحول الأحادي؛ يبقى التركيز على العنصر الصحيح |
| 1440 | وضوح محاذاة المحتوى وعدم تمديد النص بلا حد؛ البحث والقاعدة والتفاصيل قابلة للمسح البصري |

هذه اختبارات **محددة للتنفيذ اللاحق**. المرور على المخطط النصي لا يثبت التوافق على الأجهزة ولا نجاح تجربة الهاتف عمليًا.
