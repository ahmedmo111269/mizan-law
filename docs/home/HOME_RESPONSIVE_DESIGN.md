# تصميم الهاتف والكمبيوتر ونقاط التحول — «مكتب اليوم»

| الحقل | القيمة |
|---|---|
| الصفحة | «مكتب اليوم» — مركز العمل اليومي |
| المرحلة | تصميم وتحليل فقط |
| الحالة | **مقترح — بانتظار الاعتماد** |
| التاريخ | 2026-10-18 |
| الوثيقة الأم | `HOME_INFORMATION_ARCHITECTURE.md`، `HOME_VISUAL_DESIGN.md` |
| السند | REQ-001، ADQ-39 (Windows اعتيادي + Android متوسط)، الأمر §18 |

---

## 1. المبادئ

1. **Mobile-first:** تُصمَّم القائمة الموحدة أولًا على 320px، ثم تُوسَّع.
2. **RTL منطقي:** الترتيب المنطقي ثابت (البداية = اليمين في RTL)؛ لا قيم يسار/يمين مطلقة.
3. **بنية تتغير، منطق لا:** نفس صفوف العمل ونفس الإجراءات ونفس الاستعلامات في كل المقاسات؛ الاختلاف في الترتيب والكثافة والعرض فقط.
4. **لا تمرير أفقي غير مقصود** في أي نقطة تحول.
5. **لا اعتماد على Hover** في الهاتف؛ كل ما يظهر بالتمرير على الكمبيوتر له مسار لمس مكافئ.

## 2. نقاط التحول الست

| النقطة | الفئة | البنية العامة | ملاحظات |
|---|---|---|---|
| **320px** | هاتف صغير | عمود واحد؛ شريط سياق مضغوط (قائمة + بحث أيقوني)؛ شريط «الآن» صف أفقي قابل للتمرير **المقصود فقط**؛ المجرى كامل العرض؛ السكة أقسام تالية؛ شريط إجراءات سفلي | لا Side-by-side إطلاقًا |
| **360px** | شائع Android | كسابقه؛ صف العمل يعرض سطر سياق كاملًا | خط الأساس المرجعي |
| **390px** | هاتف كبير | كسابقه؛ إظهار مسؤول الصف وأيقونة إضافية دون طي | — |
| **768px** | لوحي/متوسط | عمودان اختياريان: المجرى + سكة مضغوطة، أو عمود واحد مع سكة كأقسام (تفضيل) | نقطة انتقال حذرة |
| **1024px** | كمبيوتر صغير | **البنية الكاملة:** المجرى الرئيسي + السكة الجانبية | شريط سياق كامل |
| **1440px** | كمبيوتر عريض | كـ1024 بعرض محتوى أقصى 1440px ومساحات تنفس أكبر | لا تمدد عشوائي |

## 3. تجربة الهاتف

| البند | القرار |
|---|---|
| ترتيب المعلومات | بنفس أولوية المجرى: الآن ← متأخرة ← اليوم ← … |
| الإجراءات الرئيسية | شريط سفلي ثابت: «إجراء جديد» + «البحث» + «اليوم (سكة/حصيلة)» — في منطقة الإبهام |
| أهداف اللمس | ≥ 44px لكل زر وصف |
| صف العمل على الهاتف | سطرين: العنوان + السبب؛ والسياق في تفاصيل قابلة للتوسيع؛ الإجراء الأساسي زر ظاهر لا مخفي خلف قائمة طويلة |
| الشريط العلوي | مضغوط: اسم القاعدة (مع تلميح كامل) + أيقونة حالة المزامنة + قائمة المستخدم |
| لوحة المفاتيح (هاتف بمدخل خارجي) | نفس الاختصارات المقترحة (`HD-13`) + احترام ارتفاع لوحة الإدخال (Safe Area) |
| المساحات الآمنة | احترام حواف الشاشات الحديثة (notch) وشريط الحالة |
| التمرير | رأسي فقط للبنية؛ التمرير الأفقي المسموح الوحيد: شريط «الآن» عند الامتلاء (تمرير مقصود بمقبض مرئي) |
| التفاعل اللمس | لا Hover؛ الضغط المطوّل ممنوع كطريقة وصول وحيدة |
| السياق | تغيير التصفية أو فتح سجل والعودة لا يُفقد موضع التمرير |

```

├────────────────────────────┤
│ الآن: ●جلسة 10:30 ●متأخرة  │   ← صف أفقي مقصود
├────────────────────────────┤

│ ▸ متأخرة (4)               │
│   [نوع] العنوان            │
│   سبب: متأخرة منذ يومين    │
│   [سياق: ملف كذا]          │
│   [فتح السجل] [تسجيل نتيجة]│
│ ▸ اليوم (7) …              │

└────────────────────────────┘
```

## 4. تجربة الكمبيوتر

| البند | القرار |
|---|---|
| الاستفادة من المساحة | منطقتان متوازيتان: المجرى (≈ 65–70%) + السكة (≈ 30–35%) |
| كثافة الصف | معلومات أكثر في السطر (المسؤول، وقت الاستحقاق، سطر سياق كامل) دون ازدحام |
| التنقل | اختصارات + Tab منطقي + أوامر البحث السريع |
| البحث | حقل بعرض كافٍ دائم الظهور + نتائج منسدلة مصنفة |
| التسلسل البصري | المجرى أثقل وزنًا؛ السكة أهدأ (حدود ومسافات أكبر) |
| استخدام أجزاء متعددة | السكة ثابتة أثناء تمرير المجرى (sticky) ليبقى السياق متاحًا دون تشتت |
| الشاشات العريضة | عرض أقصى 1440px؛ لا تمدد الصفوف إلى عرض الشاشة الكاملة |

## 5. كيف تتغير البنية بين الهاتف والكمبيوتر — صريحة

| العنصر | الهاتف | الكمبيوتر |
|---|---|---|
| شريط السياق | مضغوط بأيقونات وقوائم | صف كامل بحقول ظاهرة |
| شريط «الآن» | صف أفقي مقصود | صف داخل منطقة المجرى بعرضها |
| المجرى | عمود كامل العرض، صف مطوّ قابل للتوسيع | منطقتان داخل الصف (معلومة + إجراءات) |
| السكة | أقسام تسلسلية بعد المجرى | عمود جانبي ثابت (sticky) |
| الإجراءات | شريط سفلي + زر الصف الظاهر | زر المجرى + إجراءات الصفوف + اختصارات |
| شرائح الاستحقاق | تطوى وتُفتح باللمس | تطوى وتُفتح + أعداد ظاهرة |
| الكثافة | مريحة (لمس) | مريحة/مضغوطة (تفضيل) |

## 6. حالات خاصة

| الحالة | القرار |
|---|---|
| الوضع الأفقي على الهاتف | نفس البنية الرأسية؛ لا «تجربة كمبيوتر» مصغرة |
| تقسيم الشاشة (split-screen) | يُعامل كنقطة تحول عرضه الفعلي؛ البقاء في بنية عمودية آمنة |
| تكبير النص 200% | التفاف النص وتكبير الصفوف دون قص أفقي |
| لوحة الإدخال المفتوحة (بحث/تصفية) | شريط سفلي يتجنب التداخل؛ بقاء زر الرجوع يعمل |
| طول الصفوف | قص ذكي بالكلمات لا الحروف، مع العنوان الكامل في التفاصيل |

## 7. لا منطق عمل مختلف

| البند | القاعدة |
|---|---|
| الاستعلامات | نفس العقود والحدود في كل المقاسات؛ الهاتف لا يطلب «أقل» منطقًا |
| الترتيب والأولويات | متطابقان؛ الاختلاف في العرض فقط |
| الصلاحيات | فحص البيانات نفسه (ADQ-25) بلا تخفيف على الهاتف |
| حالات الخطأ | نفس الرسائل والإجراءات، بصياغة تناسب العرض |
| التخصيص | التفضيلات المشتركة تنتقل؛ ما يخص كثافة العرض فقط يبقى لكل جهاز (انظر `HOME_CUSTOMIZATION.md`) |
